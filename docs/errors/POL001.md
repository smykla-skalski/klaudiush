# POL001: Protected policy file

## Error

A tool call or shell command would change a file that enforces policy on the agent, or a shell command could not be fully inspected while protection is on. The message names each protected file and what it is:

| Kind | Examples |
|:--|:--|
| klaudiush configuration | `.klaudiush/config.toml`, `klaudiush.toml`, `~/.config/klaudiush/` |
| klaudiush state | `~/.local/state/klaudiush/` (session, evidence and exception state) |
| klaudiush binary | the running binary, `~/.claude/hooks/dispatcher` |
| hook registration | `.claude/settings.json`, `~/.codex/hooks.json`, `.gemini/settings.json`, managed settings |
| hook or evidence script | files the registered hooks or evidence checks run |
| MCP server configuration | `.mcp.json`, `~/.claude.json` |
| `protection.paths` entry | paths you protected yourself |

Each finding shows the protected path, the kind of file and the tool or program that would change it.

## Why this matters

Hooks, configuration and check scripts are what keep the agent within the rules. An agent that can rewrite them can turn any rule off, so changes to them have to come from you.

## How to fix

Leave the file alone and do the task another way. If the change is needed, tell the user what to change and why; the user can make it, or allow it:

```toml
[protection]
allow = [".claude/settings.local.json"]
```

When the message says the command cannot be fully inspected, split it into plain commands klaudiush can read.

When a Claude command already changed a protected file (reported after the command ran), restore the file and tell the user.

## Configuration

```toml
[protection]
enabled = true
paths = ["scripts/ci/**"]
allow = []
```

An exception token bypasses POL001 only when the configuration has an `[exceptions.policies.POL001]` entry.
