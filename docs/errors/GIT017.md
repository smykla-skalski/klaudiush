# GIT017: PR merge message validation failed

## Error

PR title or body, or the squash commit subject set on the merge command, doesn't follow commit message conventions for squash merge.

## Why this matters

Squash merge uses the PR title and body as the final commit message. If the PR message doesn't follow conventions, it bypasses the commit validation that normally enforces them, degrading commit history on the main branch.

The same check runs for a squash merge through the REST API, `PUT /repos/{owner}/{repo}/pulls/{number}/merge` with `merge_method=squash`, whether `gh api`, `curl`, `wget`, httpie or `xh` sends it. The pull request is fetched with `gh` from the host `gh api` talks to, or, for other clients, only from a host listed in `[validators.github.api] hosts`. A request to any other GitHub Enterprise host gets a warning instead of the title and body check, so `gh` never sends its token to a host named only by the command.

### Squash commit subject

`gh pr merge --subject` (also `-t`, `--subject=...`, `-t=...` and combined shorthands such as `-st`) and the REST `commit_title` field replace the PR title as the squash commit subject. When one is given, it gets the same title checks as the PR title: conventional `type(scope): description` format, `title_max_length`, `require_scope`, `block_infra_scope_misuse`, the revert exemption and the `enabled` switch. The PR title is still checked too, the same way the PR body is still checked when `--body` is given. An empty subject leaves the PR title in place and is skipped. On a host whose pull request is not fetched, the subject is still checked.

A variable set earlier on the same line and a heredoc are read, in both forms. A subject klaudiush cannot read, such as `-F commit_title=@title.txt`, a variable it cannot resolve, or a request body it cannot parse, is treated like `--body-file`: its content is not inspected, and the PR title is still checked.

### A REST field sent twice

With `--input`, `gh api` sends the file as the request body and moves every `-f`/`-F` field to the query string, so `merge_method`, `commit_title` or `commit_message` can arrive in both places. A URL can also repeat a key in its own query string, and httpie or `xh` send `field==value` items there too. GitHub documents these fields only as body parameters and does not say which value it reads, so klaudiush checks every value: the merge is checked as a squash when any `merge_method` value is `squash` or cannot be read, and each `commit_title` must pass the title checks. Each `commit_message` must carry the signoff, see [GIT018](GIT018.md).

## Common causes

- PR title exceeds 50 characters
- `--subject` or `commit_title` is not a conventional commit title, or exceeds 50 characters
- PR title doesn't follow `type(scope): description` format
- PR body lines exceed 72 characters
- Using `feat(ci)` or `fix(test)` instead of `ci(...)` or `test(...)`
- PR body contains forbidden patterns

## How to fix

### Fix PR title

The title must follow conventional commits format:

```bash
# Good:
feat(validator): add merge validation
ci(workflow): update build matrix
fix(parser): handle empty input

# Bad:
feat(ci): update workflow  # Use ci(...) not feat(ci)
This is a very long title that exceeds the fifty character limit
Added some changes  # Missing type and scope
```

### Fix the squash commit subject

Pass a conventional subject, or drop `--subject` to use the PR title:

```bash
gh pr merge <number> --squash --subject "feat(validator): add merge validation" --body "..."
```

For a REST merge, set `commit_title` the same way, or leave it out.

### Fix PR body

Keep body lines within the 72 character limit:

```bash
gh pr edit <number> --body "Short summary line.

Detailed description with lines wrapped at 72 characters.
Each line should not exceed this limit.

More details here."
```

### Add to merge command

Provide body via `--body` flag:

```bash
gh pr merge <number> --squash --body "$(cat <<'EOF'
Short summary.

Detailed description properly wrapped.

Signed-off-by: Your Name <your.email@klaudiu.sh>
EOF
)"
```

## Configuration

Merge message validation settings:

```toml
[validators.git.merge.message]
enabled = true
title_max_length = 50
body_max_line_length = 72
conventional_commits = true
require_scope = true
block_infra_scope_misuse = true
```

To disable merge message validation:

```toml
[validators.git.merge.message]
enabled = false
```

To allow longer titles for reverts:

```toml
[validators.git.merge.message]
allow_unlimited_revert_title = true
```

## Hook output

When this error is triggered, klaudiush writes JSON to stdout:

**permissionDecisionReason** (shown to Claude):
`[GIT017] PR title or body doesn't follow commit message conventions. Fix the PR title/body, or the --subject/commit_title, to follow commit conventions`

**systemMessage** (shown to user):
Formatted error with fix hint and reference URL.

**additionalContext** (behavioral guidance):
`Automated klaudiush validation check. Fix the reported errors and retry the same command.`
