# MCP004: Untrusted MCP server

## Error

An MCP tool call goes to a server whose provenance, as the harness reports it, matches nothing in `mcp_trust`: its Claude `mcp_server.source` is not in `trusted_sources` and no `[[mcp_trust.servers]]` entry matches its name, source, command or URL. The message names the reported server and says when the tool name claims a different one.

## Why this matters

The server name in `mcp__<server>__<tool>` is chosen by whoever configured the server, so a project can register its own server under a trusted name. Only what the harness reports about where the server came from tells them apart.

## How to fix

Use a tool from a trusted server. If the server should be trusted, ask the user to add it:

```toml
[[mcp_trust.servers]]
name = "docs"
source = "project"
```

## Configuration

```toml
[mcp_trust]
enabled = true
trusted_sources = ["managed", "user"]
untrusted = "block"   # or "warn"
```

An exception token bypasses MCP004 only when the configuration has an `[exceptions.policies.MCP004]` entry.
