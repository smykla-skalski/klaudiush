# POL002: Settings change not applied

## Error

Claude Code reported, through its `ConfigChange` hook, that a settings file changed during the session. Protection is on and the file's source is listed in `protection.config_change_sources`, so klaudiush kept the change from taking effect in the running session.

Claude Code does not show this message to anyone; it only writes a line to its debug log. The changed file stays on disk.

## Why this matters

Settings files register hooks. A change applied mid-session could remove klaudiush, add a hook that allows everything, or set `disableAllHooks`, whoever made the change.

## How to fix

If you made the change, restart the session: Claude Code loads the file at startup. To let changes from a source apply mid-session, remove it from the list:

```toml
[protection]
config_change_sources = ["user_settings", "project_settings"]
```

`policy_settings` changes cannot be blocked and always apply.

## Configuration

Register the hook in the settings that run klaudiush:

```json
{"hooks": {"ConfigChange": [{"hooks": [{"type": "command", "command": "klaudiush --provider claude --event ConfigChange"}]}]}}
```
